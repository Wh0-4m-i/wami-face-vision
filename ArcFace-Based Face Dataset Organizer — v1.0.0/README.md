# ArcFace Dataset Sorter

เครื่องมือรันในเครื่อง (local) สำหรับ **แยกรูปภาพและวิดีโอเป็นโฟลเดอร์รายบุคคล** ด้วยการจับคู่ใบหน้า
ออกแบบมาสำหรับงานจัดระเบียบฐานข้อมูลภาพ/วิดีโอขนาดเล็กถึงกลาง (ประมาณ 1–2 TB) ที่ **คัดและ Clean ไฟล์เรียบร้อยแล้ว**

> ไม่ใช่ระบบ real-time, ไม่ใช่ระบบยืนยันตัวตน และไม่ได้สร้างหรือเทรนโมเดลขึ้นเอง
> โปรเจกต์นี้คือ pipeline และหน้าเว็บที่ต่อยอดจากโมเดลสำเร็จรูปด้านล่าง

---

## 🤖 โมเดลที่ใช้

| ส่วน | รายละเอียด |
|---|---|
| ไลบรารี | [InsightFace](https://github.com/deepinsight/insightface) (`insightface>=0.7.3`) |
| ชุดโมเดล | **`buffalo_l`** (ตรวจจับใบหน้า + ArcFace recognition) |
| Runtime | ONNX Runtime — ลองใช้ CUDA ก่อน ถ้าไม่มีจะใช้ CPU อัตโนมัติ |
| Embedding | เวกเตอร์ 512 มิติ เทียบกันด้วย cosine distance |
| ขนาดตรวจจับ | `det_size = (640, 640)` |

โมเดลถูกดาวน์โหลดโดยไลบรารีตอนรันครั้งแรก **ไม่ได้รวมอยู่ใน repo นี้**

---

## ⚙️ การทำงาน

1. อ่านไฟล์จาก `Clean/` (เฉพาะไฟล์ในโฟลเดอร์นั้น **ไม่เข้าไปในโฟลเดอร์ย่อย**) ข้ามไฟล์ที่เคยประมวลผลแล้ว
2. ตรวจจับใบหน้า → สร้าง embedding → เทียบกับฐานข้อมูลบุคคล
3. จัดไฟล์ตามระยะห่าง:
   - ใกล้พอ (≤ Similarity) → `Sorted/Person_XXXX/`
   - กึ่งๆ (ระหว่าง Similarity กับ Waiting) → `Waiting/possibly_Person_XXXX/`
   - ไกลเกิน → สร้างบุคคลใหม่
   - ไม่พบใบหน้า → `Waiting/no_face_detected/`
4. วิดีโอ: สุ่มเฟรมจากช่วงต้นคลิป แล้วรวมใบหน้าซ้ำในคลิปเดียวกันให้นับเป็นคนเดียว
5. ไฟล์ต้นฉบับ **ถูกคัดลอก ไม่ได้ย้ายหรือลบ**

```
Clean/    ← ใส่รูป/วิดีโอที่คัดแล้ว
Sorted/   ← ผลลัพธ์รายบุคคล (เปลี่ยนชื่อ/รวมคนผ่านหน้าเว็บได้)
Waiting/  ← ไฟล์ที่ระบบไม่มั่นใจ รอตรวจ
```

## 🎛️ การตั้งค่า (หน้าเว็บ หรือ `POST /api/settings`)

| ค่า | Default | คำอธิบาย |
|---|---|---|
| Similarity Threshold | 0.40 | ระยะห่างสูงสุดที่ถือว่าเป็นคนเดียวกัน (ต่ำ = เข้มงวด) |
| Waiting Threshold | 0.48 | เกินค่านี้ถือเป็นคนใหม่ ระหว่างสองค่าไปโฟลเดอร์ Waiting |
| Min Face Confidence | 0.70 | ความมั่นใจขั้นต่ำของการตรวจจับใบหน้า |
| Video Scan Length | 20 วินาที | สแกนเฉพาะช่วงต้นคลิป |
| Video Frame Interval | 2.0 วินาที | สุ่มหนึ่งเฟรมทุกกี่วินาที (~10 เฟรมต่อคลิป) |

`MIN_FACE_SIZE` (50 px) และ `SAVE_EVERY_N_FILES` (10) แก้ได้ในโค้ด `face_recognizer.py`

เปลี่ยน threshold แล้วต้องการสแกนใหม่ทั้งหมด → `POST /api/reset-processed`

## 💾 การใช้ทรัพยากร และขนาดงานที่เหมาะสม

- **ประมวลผลทีละไฟล์ (ไม่ขนาน)** ใช้ GPU ถ้ามี ไม่เช่นนั้นใช้ CPU
- **RAM**: เก็บ embedding ไม่เกิน 20 ตัวอย่างต่อคน (~40 KB ต่อคน) จึงเบาแม้มีหลายพันคน
- **วิดีโอ**: ถอดรหัสเพียง ~10 เฟรมต่อคลิป เวลาจึงไม่เพิ่มตามความยาวคลิป
- **ดิสก์**: เพราะไฟล์ถูก *คัดลอก* ต้องมีพื้นที่ว่างเพิ่มประมาณเท่าขนาดข้อมูลที่ประมวลผล (ชุด 1–2 TB ควรเผื่อเพิ่มอีก 1–2 TB)
- **ทำต่อได้**: บันทึกความคืบหน้าทุก 10 ไฟล์ใน `.face_db/` หยุดแล้ว Start ใหม่จะทำต่อจากเดิม
- **ความเร็ว**: ยังไม่ได้วัด benchmark จริง ขึ้นกับ GPU/CPU และจำนวนไฟล์ ควรทดลองกับชุดย่อยก่อนรันทั้งชุด

เหมาะกับ: ฐานข้อมูลขนาดเล็ก–กลาง, ภาพใบหน้าชัด, รันเป็นรอบ (batch), มีคนตรวจโฟลเดอร์ Waiting
ไม่เหมาะกับ: กล้องวงจรปิด, ใบหน้าเล็ก/เบลอมาก, งานที่ต้องแม่นยำระดับยืนยันตัวตน

## 🚀 วิธีใช้ (Windows)

1. ดับเบิลคลิก `INSTALL.bat`
2. ดับเบิลคลิก `START.bat` → เบราว์เซอร์เปิดที่ http://localhost:5000
3. ใส่ไฟล์ใน `Clean/` แล้วกด **Start**

ปุ่มเปิดโฟลเดอร์ในหน้าเว็บใช้ `explorer` จึงรองรับ Windows เป็นหลัก

**ความปลอดภัย:** เซิร์ฟเวอร์ Flask ฟังที่ `0.0.0.0` และไม่มีระบบล็อกอิน เครื่องอื่นในเครือข่ายเข้าถึงได้
อย่ารันบนเครือข่ายที่ไม่ไว้ใจ

**ความเป็นส่วนตัว:** ข้อมูลใบหน้า (`.face_db/`, `.thumbnails/`) เป็นข้อมูลชีวมิติ ห้ามอัปโหลดขึ้น repo สาธารณะ (อยู่ใน `.gitignore` แล้ว)

**รูปแบบไฟล์ที่รองรับ**
รูปภาพ: JPG, JPEG, PNG, BMP, WEBP, GIF · วิดีโอ: MP4, AVI, MOV, MKV, WMV, FLV, WEBM
